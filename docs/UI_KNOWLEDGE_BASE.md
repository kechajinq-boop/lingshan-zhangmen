# 游戏 UI 知识库

## 使用规则

本文件持续记录当前修仙模拟经营 H5 项目的 UI 学习、设计、开发与验收结论。新增参考、确认方案或否决方案时，应更新已有结论，避免重复创建互相矛盾的规范。

## 不同游戏品类的布局规律

- 模拟经营：优先呈现主场景、资源栏、建造/管理入口、事件反馈；玩家高频操作应靠近底部或右侧便于触摸。
- 放置经营：突出收益增长、待领取状态、升级入口和离线收益；减少多层弹窗。
- 卡牌 RPG：常见底部导航与角色养成页，但不得默认套用到经营主场景。
- 修仙宗门经营：应让“宗门场景”成为第一视觉中心，资源、弟子、委托、炼丹、售卖围绕主场景组织。

## 当前项目 UI 设计规范

- 平台优先级：H5 和移动端优先，桌面 1920x1080 作为主验收视口之一。
- 主场景：建筑、角色移动和经营反馈必须清晰，不得被侧栏、弹窗或底栏遮挡核心点击区域。
- 资源区：灵石、声望、药草、丹药等核心资源必须常驻可见，数字变化应有反馈。
- 操作区：建造、招募、委托、研发、长老、速度控制等入口应保持位置稳定。
- 弹窗：只承载当前决策，不堆叠多个同级弹窗；关闭、返回路径必须明确。
- 状态：正常、点击、选中、锁定、可领取、不可用、资源不足、冷却中都应有不同反馈。
- 字体与触摸：移动端按钮和可点区域不得过小；长文本应换行或收缩，不能溢出容器。
- UI 大改流程：先生成优化模拟图或概念参考图，经用户确认后再进入代码开发。
- v0.8 已确认方向：开罗风顶部资源卡 + 微型宗门近况 + 底部分类 Tab，整体质感参考“星露谷+八方旅人”的明亮复古像素经营氛围，但保持原创修仙宗门表达。
- 宗门近况：默认微型化或可折叠，不得遮挡地图主体和建筑入口。
- 地图氛围：后续逐步减少“水泥地/硬地块”观感，强化仙山、庭院、山路、植被、水体、云雾和高低层次。

## 已确认的优秀页面

- 2026-07-31 v0.8 UI 概念图：用户确认“对味了”，认可顶部资源卡、微型日志、底部分类 Tab、木质建筑牌匾、飘字反馈和更开阔主场景视野。该方向作为 v0.8 UI 开发基准。
- 2026-07-31 v0.9 参考图确认：目标不是“只给现有 UI 加木框”，而是形成完整的修仙宗门经营场景。可复用结论：顶部资源卡必须有大图标、大数字、厚木框和纸面层次；事件栏应贴近顶部且不遮挡主场景；底部菜单应像卷轴/木案台，建筑卡片有独立图标和边框；地图必须从绿色棋盘升级为仙山庭院，包括石板广场、山体边缘、栏杆、台阶、植被、水池、云雾和远山；建筑需统一斜 45 度经营游戏透视，黑瓦木构、牌匾、灯笼、丹炉、药田、练功器械等功能元素要清晰。
- 2026-08-03 Gemini 仙山岛屿参考图：用户明确表示更喜欢“悬崖仙山小岛 + 多层平台 + 水系桥梁 + 药田中心”的经营场景。可复用结论：主场景应弱化大平面棋盘，改为有边界的浮空山体/宗门庭院；通过悬崖侧面、台阶、石板路、木桥、水池、瀑布、云雾和远山建立纵深；建筑数量不宜密集，重点建筑沿道路和平台边缘自然分布；UI 可以比 v0.9 更轻，顶部资源条简洁，底部保留少量高频入口，减少面板遮挡地图。

## 玩法界面参考结论

- 2026-08-20 寸金阁试玩反馈：右侧阅读区采用三列结构，左侧为本轮公开线索，中间固定窄栏竖排辨形、观气、问价、排伪、神识威慑五个小按钮，右侧为全程拍卖记事；功能按钮不能因容器拉伸而变大。线索定位单件宝物时，同一时刻只用一个五角星标记当前对应宝物，新线索出现后星标转移。离场筹码去向和神识威慑结果属于明确决策，使用单层弹窗承载。

## 已否决的方案及原因

- 不把卡牌 RPG 的全局底部导航生硬套用到当前经营主场景：会削弱宗门场景中心感。
- 不在当前 H5 候选版阶段大规模重构 UI 框架：会增加回归风险。
- 不保留大型左侧半透明宗门事件面板作为默认状态：会遮挡地图，降低仙山经营代入感。

## 常见 UI 问题

- 文案遮挡按钮或候选项。
- 侧栏遮挡地图左上角或建筑入口。
- 弹窗层级不清，关闭后状态不同步。
- 资源不足时按钮无反馈，用户误以为系统失效。
- 多分辨率下文字溢出、按钮过小或安全区被遮挡。

## 移动端适配规则

- 优先检查常见竖屏与横屏比例、全面屏安全区和浏览器工具栏影响。
- 核心按钮应适合触摸操作，不能只按鼠标点击设计。
- 重要反馈不能只靠 hover。
- 本地存档、资源加载和触摸拖动/点击必须作为发布前验收项。
