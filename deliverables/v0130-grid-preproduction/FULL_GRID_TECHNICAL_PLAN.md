# 《灵山大掌门》全域网格建造技术预案

状态：预处理稿，不接入当前 v0.12.2-A，不代表版本已开工。

## 已确认方向

- 普通建筑占 2×2 小格，共4格；装饰占 1×1 小格，共1格。
- 使用当前正式仙山底图和已经确认的豆包装饰原件，不替换美术。
- 概念稿合法区域共516个小格；48座普通建筑加72件装饰共占264格，剩余252格。
- 横向道路上方恢复紧邻道路的一排格；道路下方保留更宽缓冲，桥头、路口、大殿前和山门主轴继续禁建。

## 推荐实现

1. 从“48个大插槽”改为“连续小格掩码”。每格保存坐标、解锁阶段、地形类别和是否可建。
2. 普通建筑只允许从合法的2×2左上锚点放置；装饰只检查单格。
3. 道路、河流、悬崖、大殿、山门、桥梁和固定设施写入永久禁建掩码，不依赖图片颜色判断。
4. 商铺入口到最近道路节点之间设置入口走廊。走廊上的格子不显示绿色，也不允许建筑或装饰占用。
5. 装饰物保留实体阻挡，NPC不会穿树、穿石头；每次放置前临时加入障碍，再检查“山门→全部现有商铺入口”是否仍然连通。任何一路被堵，预览变红并禁止落地。
6. 新建商铺时额外检查该商铺入口是否能连到道路；无合法入口的位置不能建商铺，但仍可放普通生产建筑或装饰。

## 旧存档迁移

- 存档由schema 9升级至schema 10，并保留升级前原始备份。
- 建立固定的48项迁移表，把旧`slot-01`至`slot-48`映射到视觉位置最接近的新2×2锚点。
- 普通建筑保留UID、类型、等级、生产进度、配方、派驻弟子和库存，仅转换坐标。
- 旧装饰从原2×2位置缩为1×1，优先放在原位置的视觉中心；发生重叠时只在同一区域寻找最近空格。
- 整批迁移先在内存副本上完成并验证。只要有建筑无法安置，就不覆盖原存档，继续使用旧布局并记录诊断信息。

## 扩建与容量

- 516格是最终全解锁容量，不建议开局全部开放。
- 保留当前三阶段扩建语义，但每阶段解锁的是区域掩码，不再是固定大插槽数量。
- 阶段具体分配需要先用实机图确认；技术上必须保证旧20/32/48座建筑在对应阶段迁移后都有位置。

## 验收门槛

- 48座普通建筑与72件装饰可同时存在，仍至少剩余252个小格。
- 任意合法放置、拆除、保存和继续游戏后，占格结果一致。
- 装饰和建筑不能封死任何已有商铺路线，NPC不穿装饰。
- 旧档中建筑数量、等级、弟子、库存、资源和永久统计全部保持一致。
- 桌面和手机横屏下可准确选择1×1装饰与2×2建筑，缩放拖动后不发生点击错位。
- 新游戏、旧档迁移、建造拆除、两条生产链、NPC往返和控制台错误完成自动回归。

## 主要风险

- 这不是单纯画网格，会同时改动建造、点击、存档、相邻加成和NPC避障，必须作为独立大版本。
- 如果与灵草行情同版开发，问题定位和验收会互相干扰，因此建议放在v0.12.2-B之后。
